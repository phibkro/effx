## Outcome and scope

The existing public visitor can view a team's intake and submit a standalone application. A current nonsuspended team member can read its applications. Its current leader can revise intake and delete an application. Replace **all seven handwritten TeamApplications endpoint declarations and their raw backend binding** with one compiler-generated `team-applications` group and typed raw binding. Preserve the native HTTP, OpenAPI, generated SDK, domain, PostgreSQL, Better Auth, public form and Foldkit journey. Do not add an eighth operation or a new review/appointment state (`packages/http-api/src/team-application.ts:179-382`; `docs/system.md:496-509`).

This is one contract-and-handler migration. `TeamApplications` remains the one domain capability, and the staff editor remains one Foldkit Model. The homepage's anonymous form is a separate public React surface, not another Foldkit state machine. The service, its SQL adapter, the outbox envelope, the existing Effect `PersistedQueue` lease/retry pilot, worker triggers, and provider Layer stay hand-written. Generating an endpoint never grants team authority or changes notification delivery (`packages/domain/src/team-application/service.ts:70-143`; `docs/architecture.md:285-307`; `effx/docs/specs/0004-monoweb-migration-plan.md:318-325`).

## Behavior and authority that stay with mono-web

- **Public intake and submission.** The team and department must be active. The team must accept applications, its optional deadline must be in the future, and a deliverable team or fallback department mailbox must exist. The public form limits all seven fields. Every submission, including an exact replay, consumes the public rate limit **before** body parsing. The native handler still caps submission bytes at 131,072, decodes strictly, and records a distinct submission with a new key as another application (`docs/system.md:496-505`; `apps/backend/src/team-application/http.ts:307-394`).
- **Staff reads.** A current nonsuspended team member reads only its team's private fields. Staff credential resolution, membership lookup and AccessSpec evaluation happen inside the same repeatable-read snapshot. The service resolves the current actor before the HTTP guard emits a result. A global administrator has no implicit TeamApplications access (`docs/system.md:507-509`; `apps/backend/src/team-application/http.ts:157-223,406-474`).
- **Staff mutations and receipts.** A current team leader alone deletes or revises intake. In each serializable transaction, resolve the current principal, lock and authorize the target, evaluate the operation AccessSpec, then derive the HTTP identity and inspect any stored response. A revoked leader cannot replay an earlier success. The command receipt, attributable history, business row, outbox envelopes, queue item and HTTP response receipt keep their original atomicity. A retry of SQL serialization uses the existing receipt executor; no generated retry or new lock is introduced (`packages/domain/src/team-application/service.ts:70-143`; `apps/backend/src/team-application/http.ts:476-651`; `docs/architecture.md:96-113,285-307`).
- **Delete and intake rules.** Deletion clears undelivered private notification fields and records history without contact data or free text. Intake change requires the observed team entity tag against the _fresh locked revision_. An omitted merge-patch field leaves it unchanged; `null` clears the deadline but cannot delete `acceptApplication`. Preserve the 4,096-byte patch limit, 204 deletion, 200/new-ETag intake result and exact 409/412/428 problem behavior (`docs/system.md:507-509`; `packages/http-api/src/team-application.ts:88-94,300-359`; `apps/backend/src/team-application/http.ts:542-651`).
- **Delivery.** The confirmation means **receipt, not provider delivery**. The stored envelope keeps its effect identity and private-field policy. The queue owns leases, attempts and backoff; the outbox owns immutable message content and outcome. Delivery occurs after commit and can retry, quarantine or recover after restart. The current worker, queue migration, PgBouncer proof and provider Layer do not move into effx (`docs/system.md:502-505`; `docs/architecture.md:285-307`; `docs/specs/infrastructure-ports.md:30-65`; `packages/domain/src/team-application/service.ts:132-142`).
- **UI.** Keep the public homepage form, confirmation and privacy behavior. Keep the dashboard chooser and keyed per-team custom element. Its one Foldkit Model owns page/detail request identity, the observed intake ETag, pending mutation and stable key for an ambiguous retry. It drops stale replies and clears private data after denial or session loss. Disposal remains with the element. The generated SDK is the only native client, and the built dashboard's same-origin `/api` proxy stays in place. Staff `canManage` is display state, never a grant. There is no TeamApplications-specific `__foldkit` proxy route (`apps/dashboard/app/foldkit/team-applications/{main,model,update,view,command,browser-client,elements}.ts`; `apps/dashboard/app/routes/dashboard.teamsokn…
