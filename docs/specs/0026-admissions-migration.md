## Observable Admissions outcome and exact accepted contract

A visitor sees currently open periods and application options, submits one bounded application and can follow its confirmation. An authenticated applicant sees only their progress; an authorized period manager creates/revises a department-semester window; a current authorized outcome decider sees one scoped board and records an outcome with a fresh entity tag. A returning assistant reads options and registers through their own account, without turning Identity's separate invitation claim into an Admissions endpoint. Keep both **existing** external group names `admissions` and `admissionOutcomes`, their current OpenAPI title/description/tag, and all 14 qualified operation IDs. Do not collapse groups into a new `admissions` superset or add a synthetic fifteenth operation (`mw/packages/http-api/src/{admissions,admission-outcomes}.ts`; `mw/packages/sdk/native-api-operations.json`; `mw/packages/http-api/src/api.ts:34-70`; `mw/docs/system.md:164-218`).

`A` below is anonymous External/None/Anonymous without `PersonSecurity`; `P` is `PersonSecurity` with **one** Better Auth cookie **or** delegated Person OAuth bearer, never both. All remain External/Reveal. `CR` is optional `If-Match`/`If-None-Match`; `IK` is required `Idempotency-Key`; `IK+M` additionally requires strong `If-Match`. `D` is dynamic public conditional 200/bodyless 304 with strong ETag, Vary: Origin and the existing bounded equal `max-age`/`s-maxage` (0–30 seconds); `PC` is private/no-store conditional 200/304; `PR` is private/no-store 200; `NR` is no-store 200. Creates return 201/no-store/ETag/origin-relative Location/Vary; entity mutations return 200/no-store/new ETag/Vary. These are exact existing header-schema/response branches, not a proposed simplification (`mw/packages/http-api/src/{access,common,http-semantics}.ts`; `mw/packages/http-api/src/admissions.ts:68-324`; `mw/packages/http-api/src/admission-outcomes.ts:78-157`).

## Authority and application-owned behavior

- **Public reads and submission.** Public catalog/open-period validators depend on current period/department/field facts and a short dynamic cache; evaluate access and preconditions before a 304. The anonymous submit is still a transactional command. Keep the existing body bound, strict decode, origin policy and public rate limit **before** body parsing and receipt lookup, including replay. Within the existing database transaction, lock the command/target/email, check active eligibility, reject duplicate applicant-period submissions, and commit applicant/application/command receipt/audit/outbox atomically. A generated guard cannot become a new identity grant or move rate limiting after a replay (`mw/apps/backend/src/admission/{http-reads,http-commands}.ts`; `mw/packages/database/src/application/postgres.ts:478-648`; `mw/packages/database/migrations/{0002-admission-period-authority,0003-public-applicant-admission}.sql`).
- **Current staff decisions.** Period managers resolve current Organization reach for one department-semester under the read snapshot or write transaction. Create/revise compare current revision and strong If-Match where declared; a successful replay retains the original HTTP capsule and cannot redeliver outbox effects. Applicant progress is confined to the authenticated `profile.owner`. Returning options/registration use `placements.self` with an existing linked person/applicant and history; their command revision lives in the body. Do not merge returning registration into onboarding account claim or infer authority from the UI's navigation role (`mw/apps/backend/src/admission/{http-access,http-commands,http-reads}.ts`; `mw/packages/database/src/{admission-period/postgres,application/returning-postgres}.ts`; `mw/packages/http-api/src/admissions.ts:151-324`).
- **Outcome board and replay.** A current nonsuspended department board leader, global administrator or holder of an effective `admissions.outcomes` delegation may decide where the current authority projection allows it. A normal member can see only the scoped on-call list, not decision details; the read-one handler's **extra Decide check remains** despite the broader declared read AccessSpec. Protected reads use their existing repeatable-read snapshot. `recordOutcome` resolves/authorizes current credential and Organization facts in SERIALIZABLE preparation **before** response receipt lookup even on replay, locks the application, checks the current ETag/revision, writes append-only history, and commits its exact response capsule. A revoked actor cannot replay a formerly accepted outcome. Rekruttering's team name, a UI button, an inferred applicant result or a previously observed grant is never authority (`mw/apps/backend/src/admission/outcome-http.ts:115-175,215-345`; `mw/packages/database/src/admissions/outcome.ts:119-190`; `mw/packages/domain/src/{admissions/outcome,authz/delegation}.ts`; `mw/apps/backend/src/http-api/receipt-transaction.ts:196-321`).
- **UI and delivery stay put.** The homepage `/assistenter` form and confirmation, dashboard `/opptaksperioder`, `/soknad`, `/tidligere-assistenter`, `/vikarer`, current React Router loaders/actions and their same-origin/SSR generated SDK bridges stay application-owned. Keep existing request identity, error display, privacy/no-store, disabled/retry controls, browser disposal and axe assertions. Admissions has **zero** context Foldkit programs, so do not add a fake Foldkit adapter for parity. Period changes and application/returning commands retain their current outbox/worker and provider Layers after commit. A recorded outcome does **not** currently enqueue the intended Skolekoordinering outcome message, and neither an HTTP success nor a generated SDK call proves inbox delivery (`mw/apps/homepage/src/routes/_home.assistenter.tsx`; `mw/apps/dashboard/app/routes/{dashboard.opptaksperioder._index,dashboard.soknad._index,dashboard.tidligere-assistenter._index,dashboard.vikarer._index}.tsx`; `mw/packages/domain/src/{admission-period/effects,application/effects}.ts`; `mw/docs/system.md:200-218`; `mw/STATE.md:168-176`).
