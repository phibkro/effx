# Spec 0034 — Effect 4.1.0

Status: **build**; frozen when its PR opens. Operator request: upgrade to Effect 4.1.0 (`latest` on npm) and adopt its new features where they replace or simplify existing code.

## 1. Goal

Move the repository to `effect` 4.1.0 and its whole `@effect/*` cohort (`platform-bun`, `platform-browser`, `sql-pglite`, `vitest`, `docgen`, and the transitive `platform-node-shared`, all 4.1.0) and `@effect/tsgo` 0.63.0, with no change to what effx generates. The conformance vectors and every generated projection must be byte-identical to `origin/main` (`ee1e2939`, Effect 4.0.6), apart from the one generator change in §3.4 and the installed-version field of `manifest.json`.

## 2. Contract

1. **Pins.** `effect`, `@effect/platform-bun`, `@effect/platform-browser`, `@effect/sql-pglite`, `@effect/vitest`, `@effect/docgen`: 4.1.0 in the root, in every `package.json` that pinned 4.0.6, and in `bun.lock` (`tools/conventions/tests/effect-family.test.ts` keeps the family on one version). `@effect/tsgo` 0.48.0 → 0.63.0, the newest release, whose `effect-tsgo patch` supports the repository's TypeScript 7.0.2. It supports only Oxlint 1.88–1.90 and `oxlint-tsgolint` 7.0.2004–7.0.2005, so `oxlint` and `@oxlint/plugins` move 1.86.0 → 1.90.0 and `oxlint-tsgolint` 7.0.2003 → 7.0.2005. The vendored `@phibkro/oxlint-effect-plugin` peers `oxlint ^1.56.0` and is unchanged.
2. **Peer range (decision).** `@effx/ir`, `@effx/compiler`, `@effx/domain-model` and `@effx/persistence` now peer `effect >=4.1.0 <5`. `@effx/runtime` and `@effx/diagnostics` keep `>=4.0.0 <5`.
   - _Why the floor must rise._ `semanticHash` (`@effx/ir`), the lift patch check (`@effx/compiler`) and the lift frontend hash bytes through a digest service. Effect 4.1 removed `effect/Crypto`; its replacement `effect/crypto` (`Digest`, `SecureRandom`) does not exist in 4.0.x. ESM resolves `effect/crypto` when `@effx/ir` loads, so no code can serve both. `@effx/domain-model` and `@effx/persistence` import those two. A consumer on Effect 4.0.x that imports any of the four packages stops working at module load; that is the stated cost.
   - _Why two packages keep 4.0.0._ `@effx/runtime` (decorators and builders) and `@effx/diagnostics` use no 4.1-only API, and their sources changed in this spec only by the brand type argument of §3.3 (`Schema.TaggedError<Self, Brand>`, present in 4.0.0). The lift corpus's lower-bound consumer copies exactly those two packages' sources into a project that pins Effect 4.0.0 (`packages/frontend-ts/test/fixtures/lift-corpus/runtime/package.json`, `lift-corpus-migration.test.ts`), so their 4.0.0 floor stays verified. A consumer at 4.0.6 that uses only decorators and the bundled `effx` binary is unaffected: `@effx/cli`'s binary is built by `bun build`, which bundles Effect (`packages/cli/package.json` `build`).
   - _Two floors, kept apart._ The **target** floor (the Effect version of the project that effx analyses and generates code for) stays `>=4.0.0 <5`; generated projections use only APIs present in 4.0.0, and §3.4 adds a type argument that 4.0.0 accepts. The `stable-v4` fixtures stay on Effect 4.0.0 and keep proving it (`bindings-stable-v4.test.ts`, `dense-status.test.ts`). The **library** floor in this item is the version effx's own packages need.
   - _Packed consumers._ `scripts/stable-v4-smoke.ts` and `scripts/watch-editor-smoke.ts` install the packed cohort, so they pin their consumer to `effect` and `@effect/platform-bun` 4.1.0 (and `@effect/platform-node-shared` 4.1.0), the lowest version that satisfies every package in it. They now say so; they do not test Effect 4.0.x consumers.
3. **Crypto is explicit.** No `*Services` bundle carries it, so `scripts/native-platform.ts` exports `NativePlatform` (Bun `FileSystem`/`Path`/`Stdio` plus `BunCrypto.layerDigest` and `layerSecureRandom`). The process root `scripts/effx.ts`, the build and smoke scripts, and every test that runs a program needing a digest or a token take it from there.
4. **Output is unchanged.** `.effx/ir.json`, every `.effx/generated/*.ts`, the Alloy models and `community.vectors.json` are byte-identical, except as §3.4 states.

## 3. Breaking changes that bite this repository (file:line on `origin/main` `ee1e2939`)

1. **`effect/Crypto` removed.** `Crypto.Crypto` (`digest("SHA-256", bytes)`, `randomBytes`) became `Digest.Digest` (`digestHex(Digest.sha256, bytes)`) and `SecureRandom.SecureRandom` (`randomBytes`).
   - Library: `packages/ir/src/canonical.ts:1,45` (`semanticHash`); `packages/compiler/src/lift/patch.ts:1,188,217`; `packages/frontend-ts/src/LiftTsSourceFrontend.ts:1,34,37,84,88`; `packages/cli/src/watch-files.ts:2,139,143`; `packages/cli/src/output-owner.ts:1,88,147,204`; the requirement unions in `packages/cli/src/lift-check.ts:649`, `lift-command.ts:159`, `lift.ts:344`, `lsp.ts:618`.
   - Tooling and tests: `scripts/build-lsp-native.ts:22,109`, `scripts/build-lsp-sigpipe-test.ts:22,111`, `scripts/stable-v4-smoke.ts:2,88`, `scripts/watch-editor-smoke.ts:2,107`, `tools/testing/projects.ts:1,26`, `tools/conventions/tests/lsp-native-artifact.test.ts:3,25`, and the `Crypto.Crypto` types and substitutes in `packages/cli/test/{lsp,output-owner,watch-files,watch}.test.ts`, `packages/frontend-ts/test/lift-corpus.ts:2,101` and `lift-frontend.test.ts:23,110,120,124,179,417,422`.
   - Fix: the service moves to the new module; `Digest.digestHex` returns lowercase hex, so the three hand-written byte-to-hex conversions (`build-lsp-native.ts:104`, `build-lsp-sigpipe-test.ts:106`, `lsp-native-artifact.test.ts:17`, plus two inline ones in `watch-editor-smoke.ts:128,207` and one in `stable-v4-smoke.ts:112`) and the `Hex.encode(digest)` calls go. Output custody's 16-byte token is `Hex.encode(yield* random.randomBytes(16))`, replacing `Schema.encodeEffect(Schema.Uint8ArrayFromHex)` plus `Effect.orDie` (`output-owner.ts:28,95`). `Digest.digest` and `digestHex` have a `never` error channel, so the two `Effect.mapError` wrappers that turned a hashing failure into `CompilerFault` (`patch.ts:190-197`, `LiftTsSourceFrontend.ts:65-72`) are deleted: a failed SHA-256 is now a defect, as the module documents.
2. **Crypto left the `*Services` bundles.** Every test and script that provided `BunServices.layer` and ran a program needing a digest or a token got `Crypto` with it; 45 files now import `NativePlatform` (§2.3), among them `scripts/identity-snapshot.ts` and the root `scripts/effx.ts:38`. Two child programs written as strings, which the type checker cannot see, needed it too: `packages/cli/test/output-owner.test.ts:70-77` (found by the full run, three failing tests).
3. **`@effect/tsgo` 0.63.0 turns on nine default-on diagnostics and widens `effectNative`.** Spec 0033's rule (every default-on diagnostic is an error, source fixed) applies; `bun run effect:sync` wrote them. Findings: 60 `schemaClassMissingBrand` from `bun run typecheck` on every `Schema.TaggedError<X>()`, `Schema.Class<X>(…)` and `Schema.Opaque<X>()` (58 in 48 hand-written files, 2 in generated output), four more that only `bun run lint` reports in `packages/frontend-ts/test/fixtures/users/src` (outside the `tsc` project), and 1 `errorPayloadShadowsName` (`UnknownName.name`, `packages/cli/src/commands.ts:52`, renamed `subject`). Fix: `{ readonly brand: unique symbol }` as the second type argument, applied with one codemod over exactly the reported files and checked by `bun run typecheck` and `bun run lint`.
4. **The generated client carries the same defect.** `packages/compiler/src/generate/client.ts:360` emitted `TaggedError<TransportFailure>()`. It now emits the brand, and the tracked golden `packages/frontend-ts/test/fixtures/users/.effx/client-foldkit-generated/client.ts:21` changes with it. This is the only change to generated bytes; it type-checks on Effect 4.0.0, where `TaggedError<Self, Brand = {}>` already exists (read from the published 4.0.0 `Schema.ts`).
5. **Oxlint pins** (§2.1): `UnsupportedTargetPackageVersionError: Package @oxlint/binding-linux-x64-gnu version 1.86.0 is not supported by @effect/tsgo version 0.63.0` on the first `bun install`.
6. **Reviewed, not hit** (each searched in `packages/*/src`, `scripts`, `tools`, `examples`, `ai-docs`): `ChildProcess.make` template shell syntax (every call passes a command and an argument array: `scripts/alloy-execution.ts:73`, `build-lsp-native.ts:85,317`, `packages/cli/test/packed-watch-peer.ts:44`, `packages/persistence/test/process.ts:24`; no `shell` option, no `TemplateExpression`); custom `FileSystem` (`FileSystem.make`/`readDirectoryEntries`); `sql.insert`/`updateValues` and `Migrator.fromFileSystem`; `Toml`; `KeyValueStore`; `FetchHttpClient` streaming bodies (only the generated client's `Layer.provide(FetchHttpClient.layer)`, JSON bodies); RPC `discard: true` (the three hits are `Effect.forEach` options); `@effect/opentelemetry`; `Terminal.make`; `chunkSize`/`readSize`; `HttpMethod` (only `request.method` on a client request in `client-foldkit.test.ts:127`, which type-checks); `TestCrypto`. `BunHttpServer` loses its 10 s idle timeout: the example servers (`examples/*/src/server-main.ts`) are local demos and tests, not internet-facing.

## 4. Adoptions

Chosen:

| Adoption                                             | Replaces                                                                                           | Net                                                                                                                          |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `effect/crypto` `Digest.digestHex(Digest.sha256, …)` | `Crypto.Crypto.digest("SHA-256", …)` followed by `Hex.encode` or a hand-written byte-to-hex        | forced by the removal of `effect/Crypto`; 18 `digestHex` calls, the three `hex` helpers and three inline conversions deleted |
| `SecureRandom.randomBytes` with `Hex.encode`         | `Crypto.randomBytes` with a Schema encode and `Effect.orDie`                                       | deletes the defect-only error path in `output-owner.ts`                                                                      |
| `Layer.mock(Digest.Digest)({ digestHex })`           | `Layer.succeed(Crypto.Crypto, { ...crypto, digest })` in `lift-frontend.test.ts`                   | the release notes name it as the replacement for `TestCrypto`; the test no longer reads the real service to spread it        |
| `NativePlatform` in `scripts/native-platform.ts`     | `BunServices.layer` alone in every root, script and test, each of which would have to merge crypto | one definition, imported by 45 files                                                                                         |

Rejected, each because it would add code or a second convention rather than delete any:

- **`Glob` and `FileSystem.glob`.** The only glob uses are `Bun.Glob` in two plain Vitest tests (`tools/conventions/tests/effect-diagnostics.test.ts:166`, `oxlint-groups.test.ts:13,22`). `Glob` is tagged experimental, so adopting it needs a new EX-0037 allowlist entry; the second test matches Oxlint override patterns, and a different matcher would need its own proof that it agrees with Oxlint. Both tests are synchronous, not Effect programs. EX-0032 (TypeScript `matchFiles`) is a `tsconfig` include/exclude matcher, not a glob.
- **`Csv`.** effx emits no CSV; vectors are JSON (`community.vectors.json`, 94 MB) and the format is a spec 0032 contract.
- **`Match.literals`.** No `Match` call exists in `packages/*/src`, `scripts` or `examples`; unions of literals are decoded with `Schema.Literals` and branched with `Predicate`/`switch`.
- **`Duration.fromIso`, `formatIso`, `Schema.DurationFromIsoString`.** No ISO 8601 duration exists; durations are `Duration.millis`/`seconds` constants and `"2 seconds"` strings.
- **`Effect.ignore({ log })`.** No `Effect.ignore` or catch-to-void exists in `packages/*/src`, `scripts`, `tools` or `examples`.
- **`Pool.stats`, `PgPool.stats`, `PgClient.poolStats`.** effx owns no pool; the persistence example uses PGlite in memory.
- **`HttpApiError.Problem` (RFC 9457).** `@Http.Problems` maps typed errors to statuses and bodies the author declares (`apps/docs/content/docs/coming-from/aspnet-core.mdx`, "Automatic problem responses"); emitting `application/problem+json` changes the generated contract and is a feature spec of its own.
- **`CommandLine` and `Redacted` child-process arguments.** Every child takes a command and an argument array and carries no secret; there is nothing to quote or hide.
- **`prefer-effect-array`, `prefer-effect-record`, `prefer-effect-string`** (the three `effectNative` rules `@effect/tsgo` 0.63.0 added, not a feature of Effect itself): declined. They ask for `effect/Array`, `effect/String` and `effect/Record` in place of native members, each with a caveat the rule text states (callbacks lose the index-and-array parameters, sparse holes, `find` returns `Option`, `split` returns a non-empty array). They report 3,338 sites (2,450 array, 771 string, 117 record), and the house rule `anti-slop/no-array-filter-map` and the codebase use native arrays throughout. `tools/conventions/effect-diagnostics.ts` exports `declinedNativeRules`; `bun run effect:sync` leaves them out of the editor map, `oxlint.config.ts` out of its `effectNative` override, and `tools/conventions/tests/oxlint-groups.test.ts` fails if a declined rule turns on or leaves the preset. **Operator decision recorded here:** adopt them later only as a separate spec with its own rewrite.

## 5. Unstable APIs (EX-0037)

`effect/crypto` is tagged `@stability unstable`, as `effect/Crypto` was. `tsconfig.effect-stability.json` replaces `effect/Crypto` with `effect/crypto/Digest` and `effect/crypto/SecureRandom` in each allowlist, and adds `@effect/platform-node-shared/NodeCrypto`, the module that `BunCrypto` re-exports and that the diagnostics name. `docs/research/effect-4.0-api-notes.md` carries the re-examination under EX-0037 (examined with 4.1.0 and 0.63.0).

## 6. Falsifiers

1. **Vectors.** On the same source with Effect 4.0.6 (worktree at `origin/main`) and 4.1.0, `examples/domain-model/.effx/models/alloy/community.vectors.json` (28,072 instances, 94 MB) has the same SHA-256 (`261b9401…31f4`), and `diff -r` of `.effx` in `examples/users`, `examples/persistence` and `examples/domain-model` differs only in `manifest.json`'s installed `effect` version and, for the first two, the one `TransportFailure` line of `generated/client.ts` (§3.4). `bun scripts/identity-snapshot.ts` (190 cases: collected facts, diagnostics, canonical IR, semantic hash, SHA-256 of every generated file) is identical after normalising the worktree path, except 13 `client.ts` file hashes (the same line) and one diagnostic's line number (22 → 21) in a source file whose declaration the formatter joined onto one line.
2. `bun run typecheck`, `bun run lint`, `bun run fmt:check`, `bun run effect:diagnostics` and `bun run gate` pass on the committed head.
3. A digest service substituted through `Layer.mock` is interrupted mid-hash with exactly one cleanup (`lift-frontend.test.ts`).
4. A declined `effectNative` rule that is switched on, or that the preset drops, fails `oxlint-groups.test.ts`.
5. The lower-bound consumers (`bindings-stable-v4.test.ts`, the lift corpus on Effect 4.0.0) pass unchanged.
