# Spec 0004 — mono-web migration gap analysis and plan

Status: proposed migration contract. This document does not authorize a production cutover.

## Scope and counting rules

- `mw/` means `mw`; unprefixed paths mean this effx repository. The intended product is a modular backend, PostgreSQL, a generated HTTP client, and two browser apps (`mw/docs/architecture.md`, `mw/docs/system.md`).
- The 25 bounded-context names come from every `BoundedContext` declaration in `mw/docs/model/contexts.cml` (including six external contexts). This **to-be** map does not assert a standalone runtime module for each (`mw/docs/model/contexts.cml`, `mw/docs/architecture.md`).
- An endpoint is one `HttpApiEndpoint.{get,post,put,patch,delete}` declaration in `mw/packages/http-api/src/*.ts`. The external operation index lists 107; `InternalReceiptsApi` adds one outside external OpenAPI. There are 15 external groups and one internal group (`mw/packages/sdk/native-api-operations.json`, `mw/packages/http-api/src/api.ts`, `mw/packages/http-api/src/receipts.ts`).
- A domain-service count means concrete `Context.Service` class declarations in `mw/packages/domain/src/` (including two Delivery ports and three non-context ports); it does not count service methods. A Foldkit-model count means schemas supplied to an independent `Runtime.makeElement`, including two inline Organization models (`mw/packages/domain/src/runtime-services.ts`, `mw/packages/domain/src/notification/service.ts`, `mw/apps/dashboard/app/foldkit/organization/management.ts`, `mw/apps/dashboard/app/foldkit/organization/delegations.ts`).
- A DB-table count means distinct **main PostgreSQL tables at the registered migration head**, not the count of historical `CREATE TABLE` statements or a live database inspection. Deduplicate drops/recreations; include the migration ledger; exclude the separate Tutor proof schema. Assign each table once by the owner/subject rather than its filename prefix (`mw/packages/database/src/{migrations,schema-bookkeeping}.ts`, `mw/packages/database/migrations/0073-retire-native-school-surveys.sql`, `mw/packages/database/migrations/0075-substitute-admission-outcome-coverage-records.sql`).
- Split mixed groups by endpoint owner: `directory` has People 1 and Schools 3; `onboarding` has Recruitment 2 and Identity 1; `organization` has Organization 12 and Mailing 1; `system` has Identity 6 and shared health 1 (`mw/packages/http-api/src/{directory,onboarding,organization,system}.ts`).

## 2. Pattern mapping

A generated TypeScript declaration is never proof of runtime enforcement (`AGENTS.md`, `packages/compiler/src/generate/http.ts`, `docs/decisions/0007-cedar-authorizes-effx-issues-leases.md`).

### Authority decision for mono-web

Effx ADR 0007 records future Cedar authorization, request-scoped leases and a compile-time Cedar schema. The current compiler only records capability and focus identities; its `@Authorize` does **not** check a request (`docs/decisions/0007-cedar-authorizes-effx-issues-leases.md`, `packages/compiler/src/extensions/core.ts`, `packages/compiler/src/generate/http.ts`).

Mono-web instead already has a relationship-fact interpreter, explicit `AccessSpec`, authority writers and a transaction-time rule. Moving a mutable write decision into a pre-handler Cedar lease would allow authority to change before commit; that breaks the current contract (`mw/packages/domain/src/authz/reach.ts`, `mw/packages/http-api/src/access.ts`, `mw/packages/database/src/organization/authority-postgres.ts`, `mw/docs/architecture.md`).

**Recommendation:** generate a declarative access contract and its required guard binding, but reuse mono-web's interpreter and database lock/transaction. Resolve the principal and current facts **inside each committing transaction/retry**; keep concealment and credential evidence in the HTTP adapter. A future Cedar backend can replace the interpreter only after it proves identical relationship facts, revocation, lock ordering and denial across the same PostgreSQL journey. Leases must not outlive the transaction or authorize an independent write (`mw/apps/backend/src/profile/http.ts`, `mw/docs/model/contexts.cml`, `docs/decisions/0007-cedar-authorizes-effx-issues-leases.md`).

## 6. Operator decisions and risks

1. **Security backend:** recommend existing mono-web AccessSpec/interpreter for migration, not a simultaneous Cedar policy rewrite. Cedar/lease parity is a separate authorized gate (`mw/docs/architecture.md`, `docs/decisions/0007-cedar-authorizes-effx-issues-leases.md`).
2. **Wire compatibility:** decide whether all v0.2 headers/statuses/problem bodies and hidden internal operation remain byte/status compatible. Default: yes, because replay/credential/conditional-read assertions rely on them (`mw/packages/http-api/src/http-semantics.ts`, `mw/apps/dashboard/e2e/native-profile-self-edit.spec.ts`, `mw/packages/http-api/src/api.ts`).
3. **Codegen evaluation:** Profile maintained source increased by 159 lines when the new declarations and adapters were counted. Generated code is separate. Compare repeated declarations and bindings, legibility, and preserved journeys rather than treating a lower LOC as acceptance. Native `Effect<A, E, R>` already checks service and error channels (`docs/research/profile-slice-evidence.md:30-38`, `mw/packages/http-api/src/profile.effx.ts`, `mw/apps/backend/src/profile/http.ts`).
4. **Migrations and data:** `@PersistentModel` names a table but does not generate its constraints, history, receipt or migration. Existing applied SQL files remain frozen (`packages/compiler/src/extensions/core.ts`, `mw/packages/database/src/migration-registry.ts`, `mw/AGENTS.md`).
5. **UI boundary:** generated clients do not replace the browser-side proxy, Foldkit state machine or authentication cookie handling; keep them until an end-to-end proof shows an exact replacement (`mw/apps/dashboard/app/routes/__foldkit.profile.ts`, `mw/apps/dashboard/app/foldkit/profile/{browser-client,update,view}.ts`, `packages/compiler/src/generate/client.ts`).
6. **Cutover authority:** this is a plan, not permission to deploy, mutate credentials or retire the legacy writer. The operator controls those actions (`mw/AGENTS.md`, `mw/docs/architecture.md`).
