## 3. Decisions beyond the spec

- CLI output uses `Console.log` from `effect` (the `Console` reference service, as `ai-docs/src/70_cli/10_basics.ts` does), not `Effect.log`: `inspect`/`graph` output is the product and must be plain text (mermaid, tree), and `Console` is swappable in tests. Global `console` is never used.
- `effx check` exit 1 is modelled as a typed failure (`CheckFailed`) with `Runtime.errorReported = false`; `Runtime.defaultTeardown` maps any failure to exit 1 and `makeRunMain` skips the error log when `getErrorReported` is false (`node_modules/effect/src/Runtime.ts:108-115, 204-214, 374-400`). No `process.exit`.
- `.effx/` = `dirname(tsconfig)/.effx`, matching the frontend's default `outDir` so generated import specifiers stay valid.
- Manifest `locations` covers operation and model ids only (the only nodes with a declaring syntax); exposures/capabilities derive from the same declaration.
- Versions: `effx` from `packages/cli/package.json` (`import cliPackage from "../package.json"`), `effect` from `effect/package.json` (exported subpath, verified in `node_modules/effect/package.json`), `typescript` from the frontend.
- Spec revision of the `cli` generator (spec 0003 §"Generated CLI contract"): leaf commands must print the success encoded with `Schema.fromJsonString(Success)`; the current generator discards the result. Not yet implemented (see §5).

## 4. Gotchas

- `Schema.TaggedError` subclasses: overriding `[Runtime.errorReported]` needs `override readonly` (TS4114) because `YieldableError` declares the global marker.
- `effect/cli` shapes that typecheck: `Command.make(name, { flag }, handler)`, `Flag.String("project").pipe(Flag.withDescription, Flag.withDefault("tsconfig.json"))`, `Argument.String("name").pipe(Argument.withDescription, Argument.optional)` → `Option<string>` in the handler config, `Command.withSubcommands([...])`, `Command.run({ version })` → requires `Environment` (`FileSystem | Path | Terminal | ChildProcessSpawner | Stdio`, `cli/Command.ts:405`) — all provided by `BunServices.layer`.
- Bun 1.3.13 lowers TC39 standard decorators natively (verified with a scratch file), so `bun src/server-main.ts` in `examples/users` will work without the vitest TS6 plugin.
- `Schema.encode` with a `Struct` ignores excess properties (verified: encoding a full `User` through `User.Public` yields only `id`/`displayName`), so the generated CLI can print a handler's `User` via the `User.Public` success schema.
- HTTP server wiring (read, not yet exercised): `HttpApiBuilder.layer(Api).pipe(Layer.provide(ApiHandlers))`; `RpcServer.layerHttp({ group: Operations, path: "/rpc", protocol: "http" })` needs `RpcSerialization.layerJson` + `HttpRouter` + handlers (`rpc/RpcServer.ts:872-897`); `HttpRouter.serve(app).pipe(Layer.provide(BunHttpServer.layer({ port })))` (`http/HttpRouter.ts:1340`, `BunHttpServer.ts:330`). For tests `BunHttpServer.layerTest` gives an ephemeral-port server plus an `HttpClient` already prefixed with its origin (`BunHttpServer.ts:350-357`), which satisfies both the generated `Client.layer` (`HttpApiClient.make(Api)` needs `HttpClient`) and `RpcClient.layerProtocolHttp({ url: "/rpc" })` (`rpc/RpcClient.ts:1026`, prepends the url).
- Generated code imports schemas with extensionless relative specifiers (`../../src/schemas`); fine for Bun and `moduleResolution: bundler`.
- Root `tsconfig.json` includes `examples/**/*.ts`; the example's composition roots import `.effx/generated/*.ts` (gitignored), so `effx build` must run before the root `tsc` gate on a fresh clone. Record this in STATE.md.
- `@PersistentModel({ views: { Public: User.Public } })` would hit the class TDZ (decorator expressions evaluate before the class binding); define `UserPublic`/`UserSelf` in `schemas.ts` and reference those, assign them to `static Public/Self`.
- Interpreter diagnostics (EFFX22xx/23xx/1001) currently have no `location`; see §2.
