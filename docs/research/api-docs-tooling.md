# API documentation tooling

Decision: **`@effect/docgen` 4.0.0 works** on this bun workspace (TypeScript 7, `allowImportingTsExtensions`)
and is the API reference generator. Wired as `bun run docs:api`; the output is gitignored and built by
`bun run docs:build`.

## What Effect v4 uses

| Fact                                                                                     | Evidence                                                                                                                       |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Docgen is a public package `@effect/docgen`, MIT, 4.0.0                                  | `packages/tools/docgen/package.json` in the Effect clone; `npm view @effect/docgen version` → `4.0.0` (dist-tags `latest`)     |
| CLI is `docgen`; config is `docgen.json` (schema `schema.json`)                          | `packages/tools/docgen/README.md`, `src/Configuration.ts`                                                                      |
| It parses JSDoc (`@category`, `@since`, `@example`, `@internal`, `@ignore`, `@deprecated`) | `README.md` "Supported JSDoc Tags"                                                                                             |
| Every `@example` is type-checked with `tsc`; with `runExamples` it is executed with `tsx` | `README.md`; `dist/Core.js` `runTscOnExamples`, `runTsxOnExamples`; `tscExecutable` option (default `tsc`)                      |
| Effect's own repo also has a private `@effect/jsdocs` tool that emits JSON               | `packages/tools/jsdocs` (`private: true`), `jsdocs.config.json` → `.data/jsdocs.json`; not installable, so not an option       |
| AI docs are a separate mechanism (`ai-docs/src` → `LLMS.md`)                             | generated by `scripts/ai-docs.ts`, not by docgen                                                                               |

## Spike: `@effx/runtime` (then `@effx/ir`, `@effx/compiler`)

Installed with `bun add -d @effect/docgen@4.0.0 tsx` at the workspace root (2 s).

| Question                                  | Result                                                                                                                                                                                        |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Does it parse with TypeScript 7 installed? | Yes. docgen parses with `ts-morph` 28 → `@ts-morph/common` 0.29, which **bundles its own TypeScript 6.0** (`versionMajorMinor = "6.0"`). The root TypeScript 7.0.2 is not used for parsing. The npm peer range `typescript >=5.8.2 <7` excludes 7, but no failure was observed. |
| Does `@example` checking use TS 7?        | Yes. docgen runs `tsc` from PATH: `Version 7.0.2+effect-tsgo.0.48.0` (`bun run` puts `node_modules/.bin` on PATH). A deliberately wrong example (`.declare().nope`) failed with `TS2339: Property 'nope' does not exist on type 'ExternalOperationValue'` and exit 1. |
| Are examples executed?                    | Yes with `"runExamples": true` (`tsx`), e.g. `node:assert` checks inside the example.                                                                                                         |
| `allowImportingTsExtensions`?             | Set in `parseCompilerOptions` and `examplesCompilerOptions`; `@effx/compiler` (which imports `./x.ts`) documents without errors (28 modules).                                                  |
| Output                                    | Jekyll Markdown (`out/modules/**/*.ts.md`, `_config.yml`). `scripts/docs-api.ts` converts it: Fumadocs front matter, `meta.json` ordering, `.ts.md` → `.md`, `[Source](…)` links removed.       |

## Exact limitations and how they are handled

| Limitation (observed)                                                                                               | Handling                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `docgen` reads `package.json` **in the current directory** and requires string `name` and `homepage` (`SchemaError: Missing key at ["homepage"]`) | One project directory per documented package, `apps/docs/docgen/<name>/{package.json,docgen.json}`, with `"homepage": "about:blank"`. Real package manifests are not touched; the repo has no public URL. |
| `exclude` globs are matched against the paths as written (`../../../../packages/x/src/…`); `**/index.ts` alone did not exclude barrels | `docgen.json` `exclude` repeats the relative `srcDir` prefix.                                                                                                  |
| Example `paths` resolve relative to `out/examples/tsconfig.json`, not the project directory                          | `examplesCompilerOptions.paths` use six `../`; `types: ["bun"]` supplies `node:assert` types.                                                                  |
| One overload documented per function (upstream FAQ)                                                                  | Accepted.                                                                                                                                                      |
| Most exports carry no JSDoc yet, so pages are mostly signatures                                                       | JSDoc is the source; add `@example`/descriptions in the package. `@internal` removes a symbol from the output with no config change.                           |
| `enforceVersion` defaults to true (`@since` required)                                                                | Disabled: effx has no `@since` policy before its first publication.                                                                                            |
| `bun install` of `@effect/docgen` in a bare `/tmp` project (with `typescript@6.0.2`) did not finish in 200 s, `npm install` of the same manifest took 6 s | Observed once, cause not investigated. `bun add -d @effect/docgen tsx` inside the workspace took 2 s and is what the repo uses.                                |

## Alternatives not taken

| Alternative                                                       | Why not                                                                                                                                                  |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TypeDoc + `typedoc-plugin-markdown`                               | Works on the TypeScript compiler API and TS 7 support is unverified; no `@example` type-check/run step; docgen already gives Effect's conventions and checks examples. Kept as the fallback if docgen breaks on a TS 7-only syntax. |
| Fumadocs `fumadocs-typescript` (`AutoTypeTable`) — https://fumadocs.dev/docs/integrations/typescript | Renders one type per table inside hand-written pages; useful for field tables later, not a module reference, and does not check examples.                  |
| Private `@effect/jsdocs` JSON extractor                           | `private: true`, not published.                                                                                                                          |

## Gate

`bun run docs:api` fails when docgen fails, including a failing `@example`. `bun run docs:build` runs it
before `next build`.
