---
title: effx
description: The enterprise on-ramp to full-stack Effect. A familiar declarative surface on top, ordinary inspectable Effect underneath, no lock-in.
---

effx bridges traditional enterprise frameworks and full-stack Effect. You write a familiar declarative
surface (decorators or builder chains). The compiler reads it ahead of time and writes ordinary Effect
(`HttpApi`, `Rpc`, CLI commands, a client, Foldkit commands) that you can read, keep and edit. Effect's
typed errors and requirements stay visible, and there is no effx runtime.

```
source ──► annotations ──► IR (Schema) ──► analyses ──► generators ──► ordinary Effect
```

The one rule: **a decorator is a contribution to the IR, never generated behaviour.** The positioning is
recorded in [ADR 0012](/docs/decisions/0012-positioning-enterprise-on-ramp).
